# Java 变更工作流交接契约

仅在请求跨越两个以上阶段、需要落盘交接或恢复既有任务时使用。普通单次代码走读不创建工作流状态文件。

## 阶段与产物

| 阶段 | 最小输入 | 主要输出 | 下一阶段门禁 |
|---|---|---|---|
| 代码流程分析 | 入口、场景、终点、代码基线 | `<flow>.md`、`<flow>.flow.jsonl` | 相关路径覆盖足够；阻塞未知已解决或显式接受 |
| 宏观流程提炼 | 开发者 brief、多个 Flow Pack | `macro-flow.md`、`macro-flow.contract.json` | 状态 `frozen`；来源 digest 和基线有效 |
| 跨流程规划 | 验收结果、冻结宏观契约、Flow Pack | `change-plan.md`、`change-plan.contract.json` | 状态 `approved`；冲突和阻塞决定为零 |
| 局部方案 | 验收结果、相关代码证据 | 对话内或项目规范要求的方案 | 权威来源、完整链路、改动点和验证方式明确 |
| 实施验证 | 无阻塞局部方案或 approved plan、实现授权 | 代码改动、验证结果、残余风险 | 验收结果满足，或明确标记未验证/失败 |

## 复用规则

- 复用结构化产物前校验代码 baseline、产物版本和引用文件是否仍有效。
- 后续阶段需要结构化引用时，代码流程分析必须生成正式 Flow Pack；单轮局部变更不为留档而强制生成。
- 只加载当前决策需要的记录；影响扫描不默认读取日志、完整节点或证据附件。
- 发现过期时标记受影响切片并局部刷新，不静默混用不同基线。
- Markdown 和机器契约描述同一事实；不把两者当作相互独立的事实来源。

跨会话恢复时直接以最新源产物、代码 baseline、阻塞决定和未验证项为准，不额外维护会与源产物漂移的工作流状态副本。
