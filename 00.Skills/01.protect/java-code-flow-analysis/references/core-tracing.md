# Java 核心调用追踪

用于 `standard / deep` 分析，或存在多实现、AOP、动态分派时。数据存储、外部调用、异步和可观测性细节见 `data-and-boundaries.md`，仅在场景涉及这些边界时读取。

## 固定范围

开始前形成：`入口 + 场景条件 + 终点 + 关注点 + 版本基线`。入口可由 URL、注解、符号、Topic、任务名或业务关键词定位。区分“发起调用、完成交接、消费者入口、业务结果”等终点，只追到用户需要的位置。

## 解析真实调用关系

从调用表达式逐跳读取声明、实现、调用点和必要配置，不能凭同名文本连边。

- **多实现/重载**：结合参数类型、注入点、`@Qualifier`、`@Primary`、`@Bean`、profile、condition 和配置；不能唯一确定时列候选与缺失证据。
- **AOP/框架分派**：只接入真正覆盖当前入口并改变校验、身份、事务、缓存、重试、异步或异常语义的节点，用 `X` 表示。
- **返回/异常**：追踪结果组装、异常捕获/转换、全局处理和回滚，不把正常调用完成等同于业务成功。

每个相关直接调用分类为 `expanded / folded / boundary / out-of-scope / unresolved`。循环记录回边，不重复展开。只有确认不改变业务语义、控制、数据、事务、线程、异常或可观测性时才可折叠。

## 扫描方法内部语义

对每个展示方法检查：

- 校验、规范化、提前返回及条件值来源；
- 过滤、排序、去重、聚合、分批和截断；
- 时间窗口、金额、费率、精度和舍入；
- 状态转换、幂等、锁、事务和结果组装；
- SQL 条件、写入值、外部载荷和异常转换。

改变处理对象、范围、顺序、数值、状态、副作用或失败结果的连续逻辑合并为业务规则 `R`。记录目的、关联节点、输入来源、公式/顺序、输出、边界、影响和 reference，不为每个 `if` 建卡片。

## 证据与停止

reference 使用 `仓库相对路径:行号 · 全限定类#方法(参数类型)`；XML/SQL 使用 `path:line · namespace.statementId`，调用关系引用实际 callsite。生成或代理实现不可见时记录声明、绑定配置、调用点和 `implementation unavailable`。

默认静态分析。只有用户授权且现有测试可安全局部验证时才运行。到达用户终点、仓库/中间件边界或证据缺失处停止；未知必须说明影响和验证方式。
