# Java 数据与运行边界追踪

仅在场景涉及数据库、缓存、RPC、MQ、异步、配置、事务、日志或复杂字段血缘时使用。

## 关键数据闭环

追踪业务主键、关联键、状态、金额、时间、数量、幂等键、路由键和决定分支的参数：

`来源 → 转换/默认/筛选 → 中间载体 → 传递边界 → 可确认终点`

DTO、Command、Entity 和 Event 是载体；`save/send/submit/async` 是动作，都不自动构成终点。终点可以是数据库、缓存、索引、文件、Topic、外部接口、返回值或明确丢弃。跨仓库或缺少运行配置时，记录当前可确认边界、影响和验证方式。

## 数据操作

操作类型使用 `SELECT / SELECT_LOCK / INSERT / UPDATE / DELETE / UPSERT / MERGE / CALL`；缓存、索引和文件使用真实动作。每个关键操作记录业务目的、逻辑数据源、可确认的库/schema/表、发生条件、范围、关键字段来源、事务归属、结果影响、失败行为以及 SQL/映射证据。

实体名和 Repository 方法名不能单独证明表名。动态表、分片路由、存储过程内部表或物理实例无法确认时标为 `unresolved`。一条 SQL 涉及多表时分别说明角色；读取也要说明结果如何影响后续。

## RPC、消息与异步

- RPC/HTTP：记录目标服务/接口、关键请求与响应、超时、重试、fallback 和异常映射；没有对端源码时停在仓库边界。
- MQ/异步：证明发布调用、载荷、destination/routing、消费者绑定、监听入口和内部处理；不能证明绑定一致时列候选。
- 区分生产调用返回、事务提交、消息发送、消费成功和下游业务完成，不用上游日志代替下游证据。

## 分支、配置与事务

关键分支说明业务问题、条件、值来源、求值顺序、命中与未命中结果以及双方副作用。无后续调用时使用 `result:<结果>` 或 `boundary:<边界>`。

只记录会改变可达性、实现选择、处理范围、计算口径、重试、降级、异步交接或最终结果的配置。当前运行值只能来自用户或运行证据，仓库默认值和环境变量占位符不能冒充当前值。

事务、线程、异步、消息、RPC 和仓库外实现是语义边界；说明切换点、失败影响、重试、回滚或 ack。框架注解只证明声明，不证明某次运行已经提交或完成外部副作用。

## 关键日志

只有日志真实可达，且能证明到达、决策、交接、外部结果、状态变化或失败处置之一时才收录。记录稳定模板、变量含义、代码位置、打印条件、`before / after-return / after-commit / on-exception / finally` 时点、能证明与不能证明的事实、关联字段和级别。

调用前日志只证明准备执行；方法返回后日志不自动证明事务提交、远端完成或消费成功。建议日志与已有日志分开，避免复制敏感数据。
