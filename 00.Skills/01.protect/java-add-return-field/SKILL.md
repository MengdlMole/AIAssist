# Java 新增返回字段

本 skill 只补充返回字段特有的决策和完成条件。需要从需求推进到交付时，同时使用 `java-change-workflow`；进入代码修改阶段时使用 `java-change-execution`。

## 最小输入

从用户已有描述中取得目标项目、目标接口/方法以及字段的业务目标。只有多个候选入口或业务含义会导致不同实现时才提问；字段类型、来源和映射优先从代码证据发现。

## 字段契约

在方案或实现前明确：

- 最终字段名、类型、响应层级以及单值/集合语义。
- 权威来源及其可信边界；相似字段名不能代替来源证据。
- 空值、缺失、默认值和序列化行为。
- 权限、脱敏、租户和兼容性要求。
- 正常值、边界值和异常路径的可观察验收结果。

代码无法证明且会改变契约的事项才是阻塞未知。把“代码已证实”“用户已确认”和“待确认”分开记录。

## 链路分析

同时沿调用方向和返回方向定位：

`权威来源 → 查询/上游响应 → Entity/DO → DTO/VO → converter/assembler → Controller/RPC/方法返回 → 序列化结果`

- 找出当前链路的首次断点，而不是默认每层都需要修改。
- 检查继承、泛型、集合、分支、批量、缓存、异步、fallback 和异常映射。
- 复用项目现有映射方式；确认新增查询不会引入 N+1、无界批量或不必要远程调用。
- 字段跨边界但仍是一条可独立交付的请求/返回链时可以保持局部路线；只有多个业务流程或消费者需要共同修改、兼容和发布协调时，才按 `java-change-workflow` 的跨流程路线处理。

## 专项完成条件

- 最终字段契约与目标响应层级一致。
- 权威来源、每次转换/赋值和最终结果均有代码或运行证据。
- 使用可识别值验证每层传递关系。纯透传应满足 `权威来源值 == 最终响应值`；存在格式化、聚合或映射时，应满足已定义且可重复的转换关系。
- 空值、权限、异常、兼容和性能风险已验证，或明确报告未验证原因。
